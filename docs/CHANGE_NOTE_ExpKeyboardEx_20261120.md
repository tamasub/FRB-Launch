# FRB Launch — Exp Keyboard Ex（パンくず唯一神版）

日付：2026-11-20  
適用元：`launch_app_20261120_001009.zip`  
状態：差分実装・ヘッドレステスト済み／Windows実機でのGUI受入は未実施

## 目的と新仕様

従来の `/` は、毎回Files Expの登録ルート一覧から探索を開始していた。

**変更後は、表示中のパンくず（論理パス）を唯一の探索起点として、その直下の子項目から最初のコンテキストメニュー列を構成する。** Exp欄・Files List欄のフォーカス、選択中の行、フォルダーかファイルかは、起点判定に使用しない。

- `HOME` → My Workがパンくずの現在地なら、続けて `/` → My Work直下（ZIP／日付・定型文等）を表示。
- パンくず `FRB_Launch › docs` なら、どちらの欄にフォーカスがあっても `/` → docs直下のフォルダー・ファイルを表示。
- フォルダーEnter → 既存のFiles List着地、そこから `/` → 新しいパンくずの現在地を起点に再出発。
- `Right/Left/↑/↓`、`/`再押下・Esc閉じ、検索入力、ファイルEnter実行は既存の契約を維持。
- `/`を押しただけではパンくず、Exp登録ルート、Files List、第3列の表示先、外部アプリのセッションを変更しない。
- 真に空の階層や削除されたフォルダーでは登録ルート一覧へ自動フォールバックしない。Launch下部に状態を通知する。
- Expツリーの自動展開／折りたたみ同期方式は変更しない（別論点）。

## 内部設計

- 既存の`DirectoryAddressBar._segments`が表示している末尾の識別子を参照。仮想階層は`('virtual', page_id, item_id)`、物理階層は`('physical', path)`を利用する。PCは既存のPCナビゲーション状態を扱う。
- 表示中のパンくずと現在地が不一致なら安全停止し、Exp/Listの別の選択行から現在地を推測しない。
- 表示用の一時`QStandardItem`を`SlashExpMenu`に供給。実在するディレクトリの下位項目は読み取り専用で列挙する。Expの登録データとモデルに仮ルートを作らない。
- 登録済み物理ルートとリンクフォルダーからの着地は、パンくずの論理的な起点／マウント元を維持する。
- 最初の列は「パンくず直下」の子要素のみ。下位サブメニューには従来どおり「（カレントフォルダー）」行を残す。

## テスト・実機受入

ヘッドレスPySide6モックによる、メニュー・起点・ルート非増殖を中心としたテストを実施。**本環境にはPySide6実体がないため、Windows 11でのメニュー位置、焦点復帰、カスケード描画は実機確認が必要。**

1. HOME→`/`：My Work直下。HOMEのルート一覧が再表示されない。
2. Exp欄フォーカス／Files List欄フォーカス／中央Remoteいずれでも、同じパンくずなら同じ初期メニュー。
3. `FRB_Launch › docs`（大量のMarkdown）→`/`で直下ファイルを一覧。Rightで下位フォルダー→Enter着地→`/`再開。
4. `PC`／登録物理ルート／仮想JSONカテゴリ／JSONリンクフォルダーそれぞれを確認。
5. `/`→`/`で閉じる。Escでも閉じる。テキストエディターで`/`を入力してもメニュー起動しない。
6. 青矢印／ぱんくずEnter／第3列📂／お気に入り／Ex往復後、Exp欄最下部に未登録ルートが増殖しない。
7. Browserタブ・Studio・VS Code・サクラ・Obsidianの既存セッション／ファイル選択を保持する。

## 対象外

ExpとFiles Listのツリー展開同期の是非、外部アプリの収容／退避、追加のショートカットキー、データJSONの変更。これらは今回のスコープ外。
