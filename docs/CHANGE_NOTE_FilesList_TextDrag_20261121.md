# FRB Launch / Files List 「本文D&D」試作 — 2026-11-21

## 正本

`launch_app_20261121_102020.zip`

## 目的・制約

サクラエディタへファイルをドロップしたときにパスではなくファイル本文を挿入できる可能性を、既存のExplorerや他アプリ向けファイルドラッグを壊さず試す。

## 仕様

- Files List検索バーの右側に `本文D&D` のチェック可能なボタンを追加。**起動時はOFF**。状態は保存しない。
- **OFF**: 従来と同じ `text/uri-list`（ローカルファイルURL）＋ Copy ドロップ効果。処理を変更しない。
- **ON**: Files Listで単一の認識可能なテキストファイルをドラッグしたときだけ、ファイルURLを付けず `text/plain`（ファイル本文）を送る。
- 複数選択・フォルダー・仮想項目・対応外拡張子・大容量（1MiB超）・デコード不能・バイナリは、従来のドラッグ経路を維持。
- 文字コードは UTF-8 / UTF-8 BOM / UTF-16 BOM / CP932 (Windows日本語) を扱う。
- CopyActionのみ。Launch側でファイルの変更・コピー・削除は行わない。
- このON/OFFは **Files Listのみ**。コンパクト一覧、ポップアップ等の既存のファイルドラッグと、JSON内の並び替えドラッグは未変更。
- MIMEには本文とURLを同時に入れない（受信側の解釈揺れによる回帰を防ぐ）。

## ファイル

- `src/file_drag.py` : opt-inモードの送信経路を追加
- `src/file_drag_text.py` : 1MiB以下のテキスト読み込み（新規）
- `src/expanded_view.py` : Files ListのON/OFF操作追加
- `tests/test_text_drag_opt_in_20261121.py` : 新規テスト

## 実機確認（Windows + サクラエディタ）

1. 本文D&D **OFF**：従来どおり、Explorer / VS Code等へのファイルドラッグが変わらないこと。
2. サクラエディタの編集領域へ `.txt` を **OFF** のままドラッグすると、従来どおりの挙動（パス）であること。
3. 本文D&D **ON** にして、単一 `.txt` ファイルをサクラエディタの編集中の位置へドラッグ。**本文**が挿入されることを確認。
4. 日本語ファイル（UTF-8/CP932）と `.md` でも確認。
5. 本文D&D **OFF** に戻して、Explorerなどへの従来のファイルコピーが使えること。
