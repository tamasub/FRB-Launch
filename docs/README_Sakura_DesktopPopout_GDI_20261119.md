# FRB Launch — サクラエディタ 外出し後の画面崩れ 対応（試験版）

基準: `launch_app_20261119_193214.zip`（2026-11-19）

## 症状

サクラエディタで複数の TXT を開いている状態から URL をダブルクリックすると、サクラはデスクトップへ戻り URL は第3列に表示されるが、外出しされたサクラのメニュー／ツールバー／本文／背景色が崩れる。

## 原因仮説と変更

従来の SakuraGuestOverlay は通常の Electron / Chromium 向け Overlay と共通の `_restore_original()` を使っていた。サクラは収容中に Win32 のネイティブウィンドウスタイルを変えていないにもかかわらず、外出し時に `SW_HIDE` → `SetWindowLongPtrW` で同じスタイルを再設定 → `SWP_FRAMECHANGED` → `SW_SHOWNOACTIVATE` が実行される。これがサクラの GDI 子画面再レイアウトを乱している可能性がある。

サクラ専用に以下を実施。

- 収容時に不要な `SWP_FRAMECHANGED` をかけない。
- デスクトップへ戻す場合、不要な hide/show と、同値のスタイル再書き込みを行わない。
- 収容前の位置・サイズとトップモスト属性を復元する（Windows に正規の `WM_SIZE` が発生する）。
- スタイルが実際に変わっていた場合のみ補正し `SWP_FRAMECHANGED` を適用する。
- デスクトップへ表示後、ネイティブ非クライアント領域と子ウィンドウ全体を GDI 再描画要求。
- URLへ切替後、120ms／360msに再描画を追加（再収容された場合は中止）。
- `SetParent` や `WM_CLOSE` は使用しない。未保存テキストは編集アプリ内に保持。
- Obsidian / VS Code / Studio の Overlay / 終了制御および `state.ini` は変更しない。

## Windows実機で確認する手順

1. Launchを通常の「終了」で終了し、基準の最新版の上に差分ZIPを展開。
2. `_run_windows_Try_Sakura_Overlay.bat` で起動する。黒いDOS窓の × で終了しない（Studio NativeShell の別問題切り分けのため）。
3. TXT `001.txt → 002.txt → 003.txt → 001.txt → 002.txt` を順に開き、本文・背景色が正常か確認。
4. 任意のTXTに分かりやすい未保存テキストを入力する（例: `POP_OUT_TEST_123`。保存せずに残す）。
5. URLをダブルクリックし、第3列のBrowser表示を確認。外出しされたサクラの**タイトル、メニューバー、ツールバー、タブ、本文、背景色**を確認。
6. 再びTXTを開き、同じサクラが第3列へ戻ること、および未保存テキストがそのまま残っていることを確認。
7. これを数回繰り返す。最後にLaunchの通常終了を試す。

**重要**: 未保存の確認用テキストは、作業用の複製ファイルを使用すること。本パッチはデータの保存や強制終了をしない。

## 実行できた検証

- Python FakeWin32 による native style、デスクトップ外出し時のウィンドウ操作順序、GDI子描画、失敗時の保持、再収容時の同一HWNDの契約をチェック。
- GUI・サクラエディタ実プロセスでの画面描画確認はこのLinux実行環境では実施できていない。
- 旧いSetParent方式を前提とする過去のテストは、最新版ZIPの修正前から失敗する既存ケース。
