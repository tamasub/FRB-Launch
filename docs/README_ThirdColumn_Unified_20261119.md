# FRB Launch — 第3列統一切替 v0.3 試験差分

基準ZIP：`launch_app_20261119_200736.zip`。

## 仕様（試験版）

- 第3列の `×` と、次の URL / TXT / MD / JSON / コードファイル選択は、同じ解放規約を使用。
- VS Code / サクラエディタ / Obsidian は、管理中の元HWNDを非親子化または親子解除して **最小化**。アプリは終了しない。開いているタブや未保存編集を守る。
- C# Studio は既存の NativeShell との接続を保持し、切替時は解放・最小化。再選択では同じプロセス／HWNDへ再接続する。Launch終了時は `@FRB_LAUNCH_RELEASE@` に応答できた場合のみ、所有権を解放して生存させる（古いNativeShellなら安全のためLaunch終了を中止）。
- Browser は内部WebViewを非表示にするだけ。タブを破棄せず、読み込みも停止しない（フォーム入力途中の保護）。ただし、**Launch自体を終了した場合はWebフォームの未送信内容を永続化できない**。
- 「外に出す」ボタンは表示しない。`×` は終了ではなく「表示領域の解放」。外部ウィンドウは最小化し、タスクバーから手動で開くことも可能。
- リドック時は同じ検証済みHWNDを再利用し、先に最小化解除して表示。ウィンドウが消えていた／PIDが食い違う場合は、別のアプリを誤収容しない。
- 切替不能時は元の編集セッションを保持し、非モーダル通知。URL選択に失敗してもChromeへ勝手にフォールバックしない。

## サクラの残像対策

旧コードは、一部のタブ切替でサクラのウィンドウを **非表示にするだけ** で退避していた。今回は実際のWin32 `ShowWindow(SW_SHOWMINNOACTIVE)` によって最小化を確認する。対象はLaunchが識別したHWNDに限定し、未保存を理由に `taskkill` や `WM_CLOSE` を送らない。

※Windows実機での残像解消までは未確認。サクラが複数プロセスで動いていること自体は異常とは限らない。タスクマネージャーにプロセスが残っても、未保存タブを守るために起動状態を維持するのは仕様。

## 適用

最新版をバックアップ後、差分ZIPのフォルダー構造を維持してFRB Launchルートへ上書き展開。

起動：`_run_windows_Try_Overlay.bat`（既存）。互換名として `_run_windows_Try_Sakura_Overlay.bat` と `_run_windows_Try_VSCode_Overlay.bat` も同梱。

この差分は **state.ini と本番ビルドBATを変更していない**。PyInstallerは通常のimportを追うため、新規Pythonモジュールは次回ビルド時に自動収集される想定だが、実機ビルドは未検証。

## 実機回帰手順

1. サクラで 001.txt → 002.txt → 003.txt を開き、未保存文字を入力。
2. URLをダブルクリック。サクラが**最小化**され、Browserが第3列に表示されるか確認。
3. 001.txtを再選択。**同じタブ群・未保存文字**で第3列へ戻るか確認。
4. 別のサクラタブに戻り、残像・背後の空白窓・別ウィンドウが残らないか確認。
5. サクラ表示中にStudio用JSONをダブルクリック。ダイアログなしで切替可能か確認。
6. 同様にMarkdown/Obsidian、VS Code、Browserの相互切替を確認。
7. 第3列 `×` でウィンドウを最小化し、再選択で再収容。
8. Launchの通常の「終了」操作で外部アプリが保持されるか確認。**黒いコンソールの×による強制終了は試験しない**。
