# Keyboard Ex 性能改善 Phase 1–4（2026-11-25）

基準: launch_app_20261125_195823.zip

## 判断軸・制約
- 人間の操作応答性を優先する。
- 現在の階層より深い物理フォルダーの中身を、選択前に列挙しない。分岐判定はメタデータで行う。
- 既存の Right / Enter / Left / Esc / IME / 検索 / ファイル選択モードの責務を維持する。
- 今回は GUI の非同期化・仮想リスト化・索引変更を混ぜない。設定・バージョン・ユーザーJSONは変更しない。

## 対応
- `_branch_actions` は展開可能性だけを保持。`_submenus` は明示操作で生成した実メニューだけを保持する。通常のフォルダー Enter は子メニューを生成せず既存の Files List 遷移を呼ぶ。操作メニューも遅延生成。上下移動やフィルタで未生成メニューを作らない。
- 物理フォルダーの空判定は事前に行わない。空でも右矢印を表示し、開いた時点でカレントフォルダー行（選択専用モードでは項目なし）を表示する。既知の空のJSONカテゴリは従来のコンテキスト動作を維持する。
- 通常の一時的な物理ルート（breadcrumb / 検索結果 / ファイル選択）では `scandir` 一回でフォルダー・ファイルを分類。既存 Exp モデルの未展開物理行は登録ルートの同一性を守るため従来のモデル展開を維持し、別途ファイル列挙する場合がある。JSON子一覧が既知なら既存Expを展開せず投影。リンク先は展開時に読み、必要な一時行は独立ホルダーに作る。
- 2種類の列幅がいずれも300pxであるため不要な全件幅計測を省略（既存の列幅・文字省略は維持）。フォルダーアイコンの共通取得。
- 同じ `/` セッション内では開いたサブメニューを再利用し、閉じて `/` を押し直すと新しいセッションとなる。

## Expected / Actual
Linux / headless Qtスタブによる計測。120子フォルダー（各1ファイル）+ 150直下ファイルを持つ一時物理ルート。

| 初回 子メニュー生成数 | 120 | 0 |
| 表示対象行（カレントを含む） | 271 | 271 |

右キーで子を開くと当該子だけ1回列挙。上下移動・選択中の未展開枝への先行列挙なし。戻って再度開くと同一セッション内で再利用。新規3テスト PASS。関連試験は変更前166 PASS / 11 FAIL、変更後169 PASS / 同じ11 FAIL（新規FAILなし）。FAILは既存のテーマ・表示位置・旧バッチ不在・既存フォーカステストスタブ等。変更された旧テストは先行生成を前提にしていた内部実装の期待を遅延生成の契約に置換し、右操作後の表示・既存操作の検証は維持。

## 実機確認
1. Launchを完全終了、差分を上書きし `_build_windows.bat` でビルド。
2. 多数の子がある場所で `/`、上下、右、左、Enter、Esc、文字検索・日本語変換、マウスクリックを確認。Commanderのファイル選択モードも確認。
3. `%LOCALAPPDATA%\FRBLaunch\launch.log` の `KEYBOARD_EX_PERF` を確認。

```powershell
Get-Content "$env:LOCALAPPDATA\FRBLaunch\launch.log" -Tail 500 | Select-String 'KEYBOARD_EX_PERF'
```

- `phase=populate`: rows/branches/created、rows_ms（行データ取得・アイコン・ソート等）、actions_ms（幅・検索欄・QAction生成）、viewport_ms（長い一覧のQTreeWidget生成等）、total_ms。
- `phase=root_open` / `phase=child_open`: 各処理が戻るまでの所要時間。OSが実際に描画完了した時刻ではない。root_openはpopup_exp_navigator呼出から計測、呼出前のショートカット起点解決は含まない。
- パス・検索文字・コマンド内容は今回の計測ログに記録しない。
