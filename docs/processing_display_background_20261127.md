# 処理中担当者：白画面対策（2026-11-27）

基準: `launch_app_20261127_220908.zip`。

## Context / Accountability

GitコミットのMESSAGE画面が真っ白になる報告。ソース上はラベル・タイマーが存在するが、コミットの複数の同期Git呼び出しがGUIスレッドを占有している。実機での原因確定は未実施。

処理中担当者は、処理の実行中も処理中表示を維持し、終了（異常を含む）時に解除する。個別メニューには描画対策を持たせない。

## 対応

- `src/processing_display.py`: 共通 `run_background()` を追加。GUIに依存しない処理をQThreadで実行し、GUI側はイベントループを維持する。Qtのキュー接続で完了を受け、ワーカーをjoinして元の結果または例外を返す。MESSAGE/PROGRESSのモーダル表示が対象（CURSORのみの同期入口は既存の `run()`）。PROGRESSの詳細な進捗通知は今回新規入口に追加していない。
- `src/app.py`: 確認後のGitコミット本処理を共通入口に接続。リポジトリ選択、変更プレビュー、最終確認、コミット対象、結果通知は従来どおり。Gitの事前プレビューは引き続き同期処理。共通処理中画面は非キャンセル式であるため、Escapeによる誤閉鎖を抑止。
- コピー・移動の既存ワーカー、Windows Shell削除、メニュー閉鎖、バッチコマンダー、ファイル索引は変更しない。同期処理全体のバックグラウンド化は今回の範囲外。

## Expected

MESSAGE/PROGRESSを伴うバックグラウンド処理の実行中に、処理中画面が描画・更新される。処理終了時には画面が閉じ、砂時計が解除される（外側の処理が継続していれば維持する）。業務結果・例外の意味は変更しない。

## 検証

重点テスト: 21 PASS、1 SKIP（PySide6なし）。関連テスト合計: 33 PASS、9 FAIL、2 SKIP。改修前は同じ既存テスト群で24 PASS、11 FAIL、1 SKIP（新規テストを除く）。残る9 FAILは改修前にも発生していた同じケース。Gitリポジトリ手動選択テスト2件は古いダイアログ呼び出しのテストダブルを現行契約へ更新し、実Gitリポジトリでの成功・選択なしの両ケースを確認。実Qtの描画テストは同梱するが、この環境では未実施。

Windowsでの確認: Gitコミットを承認した直後に「Gitコミットしています…」が表示され、処理中のスピナーが更新されること。終了・失敗で画面が消えること。コピー・移動・削除の表示に変化がないこと。短い処理では画面を見せる目的だけで完了を遅らせない。
