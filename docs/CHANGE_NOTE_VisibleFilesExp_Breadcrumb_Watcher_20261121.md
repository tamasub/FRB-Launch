# FRB Launch: 可視Files Exp＋ぱんくず自動反映（2026-11-21）

## 適用元
`launch_app_20261121_112848.zip` を正本にした差分。ZIPの相対パスをLaunchルートへ上書き展開。

## 対応
- **Files List**：従来の自動更新（F5再読込を300msまとめ）を維持。
- **Files Exp（埋め込み／独立）**：画面上の行だけを調べ、表示されたフォルダー名の親、展開済みフォルダー自身をファイルシステム監視。子を追加／名前変更／削除した親ディレクトリに限り、既存の `refresh_directory_branch()` を使用。展開・カレント・スクロールの保存処理を再利用し、Filesの履歴／フォーカスの移動は行わない。
- **可視領域の更新**：スクロール、展開、折りたたみ、リサイズ、表示／非表示、モデル変更時に監視を再選択。監視対象は最大48フォルダー。同時更新通知は300msでまとめ、100msの監視先入れ替え遅延。
- **ぱんくず**：表示されている物理ディレクトリ階層の「名前を持つ親」を監視（最大32件、重複排除）。JSON仮想フォルダーは無対象。変更通知は300msでまとめ、通常は表示ラベルのみ再構築。
- **現在位置のフォルダー名変更**：`os.stat` のファイルIDが利用でき、**同じ親の下での名前変更**を確認できる場合に限り、現在の実フォルダーに追従。選択中のファイル名とListスクロールを可能な範囲で復元し、履歴への新規追加を防止。
- **安全**：編集中／ドラッグ中／ダイアログ表示中は更新を延期。遅延通知は対象照合で無視。Expの再読込は既存の非ナビゲーション処理。Browser表示中／Exp非表示中の監視は停止。

## 制限と非対象
- Windows実機のQt `QFileSystemWatcher` イベント到達と描画・カレント行追従は未検証。実機で確認すること。
- 登録済みFilesルートやJSONリンク先は設定で管理する参照先のため、Explorerによるそのルート自体の名称変更／移動を、Launchの保存設定に自動反映しない。
- フォルダーの別親への移動、複数回連続した移動、ネットワークドライブ等でファイルIDが得られない場合は、誤追従を避けて現在位置を勝手に変更しない。
- 可視範囲外・閉じたExp下層は監視しない。元の対象ディレクトリがなくなったときは、登録のリライトや近隣フォルダーへの自動ジャンプを行わない。
- 初期の大容量フォルダー／低速NASでは、通知後の枝再読込に時間がかかる場合がある。

## 回帰テスト
- 変更モジュール `py_compile` 成功。
- 新規 Qt-free テスト10件成功（監視の重複排除・可視対象・仮想階層除外・通知集約・リネーム中延期・同一ファイルIDによる追従・旧通知拒否・可視モデル走査）。
- 関連全体: 70 PASS、13 FAIL（同じ旧テスト群を元ZIPで実行したときも13 FAIL）。増加した失敗は0。
- このLinux実行環境にはPySide6がないため、WindowsのD&D・イベント実機検証は代替できない。

## Windows実機チェック
1. Expでフォルダーを展開し、Explorer側でそこにサブフォルダーを追加・改名・削除：操作せず画面が変わるか。
2. Expをスクロールして別の位置を表示した後も更新するか。フォルダー展開状態・カレント・スクロールを確認。
3. ぱんくずに現れている（登録ルートより下の）物理フォルダー名をExplorer側で改名：パスとListが追従するか。
4. ExpまたはFiles Listでリネーム編集中に更新が割り込まないか。
5. Browserへ移動しても不要な更新が起きず、Filesへ戻ると最新状態になるか。
