# FRB Launch `/` 矢印ナビ — メニュー位置・操作性修正（2026-11-18）

## 基準と適用

- 基準ZIP：`launch_app_20261118_132804(1).zip`（同名の先行アップロード `launch_app_20261118_132804.zip` とバイナリ一致）
- 本成果物は**差分ZIP**。既存の FRB Launch ルートにフォルダー構造を保ったまま上書きする。
- 設定JSON、登録項目、既存のファイルデータは同梱・変更しない。
- Windows起動中の Launch は終了してから適用する。

## 改修内容

1. **アイコンなし行の左寄せ**：QMenu全体でアイコン余白が予約されても、アイコンなし行は左端に名称を描画する。アイコン付きの行は既存アイコンを維持。
2. **検索欄の右端切れ**：QLineEdit のCSSマージン任せを廃止し、QWidget + QHBoxLayout の左右余白内に配置。各列で検索可能。
3. **長い項目名**：表示ラベルを Qt の `elidedText(..., ElideRight, ...)` で省略。元の名称を検索とツールチップに保持。
4. **末端のコンテキスト表示位置**：元の `FRBContextMenu(Qt.Tool)` を直接子ウィンドウ化する方法を廃止。既存コンテキストメニューからQAction／コマンドを読み取り、`SlashExpMenu(Qt.Popup)` の次列として表示。
5. **コンテキストメニューのキー操作**：上下キーで選択、右キーでさらに下位の操作メニュー、左キーで一段戻り、Enterで選択した**元のQAction**を実行。途中のEnterは無効。検索欄がフォーカスされていても矢印はメニューに転送。
6. **第3列を含む接続**：末端の右キーで開くコンテキストもExp／仮想フォルダーと同じ階層管理。元のウィンドウ座標で浮遊させず選択行の隣へ配置。右側に足りない場合は画面内に収まる側に隣接配置。
7. **遠くに展開する問題**：Windowsや複数モニターで発生しうるQMenu自動配置を補正。初回 `/` 表示時は最大4列分の横幅を意識して開始位置を画面内で調整する。子列は選択行のグローバル座標に合わせて移動。

## 操作仕様（維持）

- `/`：開く／閉じる（起動直後の有効化は既存 `src/app.py` の実装を維持）
- `↑↓`：現在列の選択移動のみ、勝手に展開しない
- `→`：子階層を開く。末端ならコンテキストメニューを開く
- `←`：一段戻る
- 中間階層の `Enter`：何もしない
- 末端の `Enter`：従来のFiles List／Launch実行経路に委譲
- コンテキストメニュー内の最終 `Enter`：元のQActionを実行
- `Esc`：一連の `/` メニューを閉じる
- 長いメニューはLaunch本体の高さ約70%を上限とする既存ルールを維持
