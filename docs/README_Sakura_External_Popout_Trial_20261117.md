# FRB Launch — サクラエディタ取り込み／外に出す／× 明示操作 試作

対象元ZIP：`launch_app_20261117_172933.zip`（2026-11-17）

## 基本契約

- `.txt` / `.ini` のダブルクリック：従来どおりサクラエディタに渡す。第3列収容は既存の `embed_sakura` 隠しオプションに従う。
- 既に外側でサクラエディタのウィンドウが **1つ** 起動している場合：「Launchの中に取り込んでいいですか？」と必ず確認する。
- 「いいえ」：収容しない。従来の外側で開く経路を使用する。
- 「はい」：確認されたウィンドウだけを第3列に収容する。タブを閉じたり並べ替えたりしない。
- 第3列収容中：別の `.txt` / `.ini` ファイルをダブルクリックしても**同じサクラエディタのタブに渡す**。既存のタブの選択・切替を理由に、自動的に外へ戻したり終了したりしない。
- 第3列右上の **□↗（外に出す）**：サクラエディタのウィンドウをデスクトップへ戻す。**終了要求は出さない。** その後第3列を閉じる。
- 第3列右上の **×**：収容中のサクラエディタウィンドウへ**通常の WM_CLOSE** を1回要求。未保存ファイルがあればサクラエディタ自身が確認。確認をキャンセルした場合は第3列を残し、編集を続けられる。
- 通常の別プレビューへ切り替える操作／Launchの自動非表示では、収容中のサクラエディタを勝手に外へ出さない。
- Launchアプリ自体を終了する場合、サクラエディタの収容を解除して終了してよいか確認する。キャンセルならLaunch終了もしない。
- ファイルごとにプロセスやタブを終了する動作は追加していない。
- StudioとObsidianの独自の表示・保存処理は変更していない。

## アイコン

提示画像と同じ趣旨の「四角から右上へ出る矢印」。既存の `browser_navigation_icon('external')` を利用するため、別の画像ファイルは不要。サクラエディタが第3列へ収容されている間だけ表示する。

## 適用方法（src事故を防ぐため差分ファイルを自動選択）

1. 最新Launchをバックアップする。
2. このZIPの**中身**をLaunchプロジェクト直下（例 `F:\FRB_Apps\FRB_Launch`）へ展開する。展開後に `Apply_Sakura_Popout_20261117.bat` がLaunch直下にあることを確認。
3. `Apply_Sakura_Popout_20261117.bat` を実行。
4. スクリプトは既存の `src/app.py`、`src/expanded_view.py`、`src/studio_preview_panel.py` が揃っていることを先に確認し、変更対象ファイルだけバックアップして更新する。`src` フォルダーの移動／置換はしない。
5. Launchを再起動。ソースから実行する場合は再ビルド不要。EXE版の場合は再ビルドが必要。

## Windowsでの要実機確認

1. 単独起動のサクラエディタで `.txt` を開く → Launchから別 `.txt` をダブルクリック → 取り込み確認「いいえ」→ 外のサクラエディタはそのまま。
2. 同条件で「はい」→ 第3列へ収容 → 既存タブを手動で切替 → 第3列から勝手に飛び出さない。
3. 新しい `.txt` と `.ini` を続けて開く → すべてサクラエディタ側のタブで管理される。日本語入力と Ctrl+S が使える。
4. □↗ → **サクラエディタは終了せず**デスクトップへ戻る。タブ／未保存内容を保持。
5. 第3列で未保存の編集 → × → サクラエディタの保存確認が出る → **キャンセル** → 第3列が残ること。
6. 第3列で保存済みの編集 → × → サクラエディタが正常終了し、第3列が閉じること。
7. サクラエディタを収容したままLaunchを終了 → 承認ダイアログ。拒否時は終了しない。

**注意:** Windowsのクロスプロセス `SetParent` / Qt / サクラエディタのタブモードは実機依存。今回のテストはロジック確認であり、実際の保存確認・Tab管理・OS上の安定性はまだ検証していない。`WM_CLOSE` は通常終了依頼であり、プロセス強制終了ではない。サクラエディタが常駐する実装／設定の場合、編集ウィンドウを閉じても補助プロセスが残ることがある。
