# FRB Launch / Enterと列タイトル操作の統一（2026-11-19）

## 適用元
`launch_app_20261119_125507.zip` に対する**差分**。Launchルートに展開して変更ファイルを上書きする。Studio NativeShell の変更・再ビルドは不要。

## 変更

1. Files Listの末端行（管理JSON、Markdown、物理ファイル、登録URL・ブックマークURL）の **Enter** を既存の **ダブルクリックと同じ** `preview_bookmark_from_list()` へ先に渡す。処理済みなら `launcher.activate` は二重実行しない。ディレクトリ・カテゴリのEnterナビゲーション、F2インラインリネームのEnter、選択・Shiftキー操作は従来通り。
2. FRB Launchタイトル文字・葉っぱアイコン・上部の空白、Files見出し、Files Exp、Files List見出しを **ドラッグ移動**／**ダブルクリックでLaunch全体を最大化・復元**できる操作面にした。検索入力・パンくず・ボタン・リストの列見出しは操作面に含めない。
3. 第3列（Browser／Studio・Obsidian共有）の**タイトル部分をドラッグ**できる。タイトルをダブルクリックすると、**Launch全体が通常表示ならLaunch全体を最大化**、**すでに全体最大化なら第3列のLaunch内最大化／元に戻す**を切り替える。第3列右上の最大化・閉じるボタン自体は従来通り。
4. Qtの `startSystemMove()` をドラッグ開始前に呼ぶとWindowsがダブルクリックを奪い得るため、明示指定されたタイトル面では**数px動いた後に移動を開始**する。旧来の通常パッシブ面は既存動作を維持する。
5. 既存ぐりぐりボタンの配置ロジック・Splitter接続は変更しない。最大化によるサイズ変更時は既存の再配置処理を使う。

## 検証

- PySide6なしのLinux開発環境でPython構文チェック成功。
- 新規専用テスト9件PASS。関連を含む67件PASS。
- 関連ソースを検査する34ファイルの広範囲テスト：修正後271件PASS／44件FAIL、修正前262件PASS／44件FAIL。**差分で増えた失敗0件**。44件の既存失敗には旧Browserタブなど旧仕様への依存が含まれる。
- Windows11 + PySide6での実際のドラッグ・最大化・Dock中の第3列表示およびぐりぐりの位置は未検証。上記テストはUI実機評価の代替ではない。

## 推奨実機チェック

1. Files ListでStudio管理JSONと `.md` をそれぞれ**ダブルクリック／Enter**して、どちらも第3列に出るか確認。
2. Files Exp/Listのタイトル・左上FRB Launchロゴ／タイトルをドラッグしてLaunch全体が移動するか。
3. それぞれのタイトルをダブルクリックしてLaunch全体最大化／復元できるか。
4. 第3列タイトルを**通常表示でダブルクリック**してLaunch全体最大化、**全体最大化中にもう一度ダブルクリック**して第3列最大化／元の幅へ戻るか。
5. 第3列を×で閉じる、再表示する、ぐりぐり操作位置がずれないかを確認。
