# FRB Commander — 入力欄固定・候補一覧フローティング化（2026-11-24）

## Expected / 目的

候補を表示・絞り込み・閉じるたびに Commander 本体のレイアウトが動いてしまう問題を解消する。
「入力欄（ユーザーの視線とキー入力の起点）は動かさず、候補一覧のみ本体枠外へ展開する」という
超わがままサーチ / Keyboard Ex に近い操作体験を目標とする。

## 変更点

- `src/commander/window.py` の検索欄を **メイン画面の固定レイアウト**に常設。
- 候補一覧は `QFrame` の独立した **Qt.Tool（ネイティブ別ウィンドウ）** に移動。
- `Qt.Popup` は使用しない。候補側は `WindowDoesNotAcceptFocus`、`WA_ShowWithoutActivating` とし、
  入力欄のフォーカスおよび IME を奪わない設計。
- 入力欄の直下に表示し、モニター端では上下左右を補正。Commander 移動・リサイズにも追随。
- 候補表示・検索・キャンセルで Commander 本体をリサイズしない。
- 入力中の `↑↓` は候補移動、`→ / Enter` は確定、`← / Esc` はキャンセル。
- 自由入力（`input=text`）は常設欄のみ使用し、不要な候補ウィンドウは開かない。
- 候補表示中の `Ctrl+Enter` では未確定の選択を実行しない。
- ファイル選択は引き続き既存 `Keyboard Ex` を使用。ViewDef / PowerShell の変更なし。

## 適用方法

FRB Launch を終了し、差分 ZIP を **Launch のルートフォルダーに、階層を保持して上書き**。
その後 Launch を再起動する。既存の設定 JSON や `.viewdef` のコピー・変更は不要。

## Windowsでの目視確認

1. Commander起動。入力欄が初めから表示されている。
2. `↓` で比較方法を選択。候補はメイン枠の外へ別ウィンドウとして表示され、検索欄の画面上の座標と本体サイズは変わらない。
3. 候補検索しながら `↑↓ → Enter` で確定できる。`Esc / ←` で閉じたときも欄の座標は変わらない。
4. 別の比較方法を選び直す。候補が再度表示されても本体のレイアウトは動かない。
5. 「2ファイル比較」で Keyboard Ex を開き、ファイルパス選択と次ステップへの遷移を確認。
6. Commander をドラッグして移動。候補の位置が検索欄に追随する。
7. メインを閉じた後、浮遊ウィンドウだけが画面に残らない。
8. `Ctrl+Enter` から実行確認へ進める。**実行する場合は出力先の上書きに注意**。
