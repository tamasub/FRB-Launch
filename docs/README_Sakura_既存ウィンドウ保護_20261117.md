# FRB Launch — サクラエディタ既存ウィンドウ保護（2026-11-17）

## 対象
- `launch_app_20261117_165740.zip` に、前回の `FRBLaunch_SakuraFocus_VisibleClose_20261117_diff.zip` を適用した状態
- Launch の第3列サクラエディタ埋め込みを有効にした実験環境

## 変更目的
既にユーザーが単独起動しているサクラエディタを Launch が勝手に収容・閉じることを禁止する。成功している文字入力フォーカス対策は維持する。

## 仕様・安全策
1. サクラエディタを起動する直前に、既存の編集ウィンドウ（非表示を含む）とその PID を記録する。
2. 第3列の収容対象は、起動前には存在しなかった HWND かつ既存の編集 PID に属さないウィンドウのみ。既存アプリ側がタブ／ウィンドウを再利用したときは無理に収容しない。
3. Launch が実際に収容を完了したサクラエディタの HWND と PID の対応を記録する。
4. 第3列の × と他のエディタへの切替で送信する WM_CLOSE は、Launch が記録した HWND だけを対象にする。終了直前に PID を照合し、違う場合は送らない。
5. 所有権が確認できないサクラエディタは、第3列から外して通常ウィンドウに戻すだけで終了要求を送らない。
6. 保存・未保存確認はサクラエディタ自身が行う。強制 kill やプロセス名一括終了はしない。
7. Obsidian、FRB Studio、Browser Preview、キーボードフォーカスの既存処理は変更しない。

## 注意
- 既存サクラエディタのタブに Launch からファイルが追加された場合、既存ウィンドウを奪わず第3列への収容は見送ることがある。安全優先の仕様。
- サクラエディタの制御／常駐プロセスはウィンドウと別のため、×の後に全関連プロセスがなくなることまでは保証しない。
- Windows実機での表示／編集／保存／未保存確認は未検証。テスト用の `.txt` と `.ini` で確認すること。

## 推奨確認手順
1. サクラエディタを単独起動し、未保存のテスト文書 `standalone.txt` を開いておく。
2. Launch から別の `launch-test.txt` をダブルクリックし、第3列に収容される場合は文字入力できることを確認する。
3. 第3列を × で閉じる。
4. 単独起動していた `standalone.txt` のウィンドウが残り、未保存内容もそのままであることを確認する。
5. Launchから `1.txt` → `2.txt` → `3.ini` を開く。既存アプリが再利用されたときは収容が見送られることがある。
6. Launchを終了しても、先に単独起動していたサクラエディタを使い続けられることを確認する。

## 適用
ZIP内の変更ファイルだけをプロジェクトへ上書きする。`src` フォルダーを丸ごと置換しない。
