適用：この差分ZIPの相対パスを FRB Launch のルートへそのまま上書き。過去差分の再適用は不要。

## 変更点

### 1. Files List × Slash メニューのカラー試作
- **ダークのFiles List背景 `#463a32` は一切変更しない**。お気に入りの茶色を保持。
- **ライトのFiles List背景**だけ、従来の `#FFFEF9` から、茶色の要素を少し足した淡いベージュ `#F7EEE4` へ試験変更。
- `/` の浮遊メニュー背景を、どちらのテーマでも **現在のFiles List背景と同じカラー** にする。検索欄・ホバー・仕切りも同じ暖色系に統一。
- 選択行は既存のテーマ色を尊重。通常の右クリックコンテキストメニューやExp欄本体の色は変更しない。
- 既存の List 本体とメニューの色がバラバラにならないよう、共通パレット `files_list_active_bg` を参照。

**配色は未確定・A/B試作**：`src/launch_appearance.py` の `SLASH_FILES_LIST_COLOR_TRIAL = True` を `False` にすると、**メニューだけ**2026-11-20 18:45時点の色へ戻る（アプリ再起動後有効）。位置・枠線はそのまま。ライトのList背景を元へ戻したい場合は `files_list_active_bg`（light）を `#FFFEF9` に戻す。ダークのList背景は変えていない。

### 2. 確実に四辺が見える細い枠線
- 角丸10pxは維持。
- QMenuの1px CSS枠線に加え、透過QMenuの最前面に細い角丸アウトラインを描画。**下辺を含む四辺**を明瞭にする。
- Windows の標準的な影より細線を優先するため、利用可能なQt環境では `NoDropShadowWindowHint` を指定。影の扱いはOSやQt版に依存する場合あり。
- 色・境界線の変更は `SlashExpMenu` に限定。通常メニューは変更なし。

### 3. カレント行のフォルダー名のすぐ右から展開
- Files List：DataJSON `title` が長い実パス等を保持していても、**画面に実際に表示される `item.text(0)`** の幅でメニュー左位置を計算。フォルダー名の右側に約14pxの余白。
- Exp：階層インデントを `visualRect().left()` から取得して、深い階層でも名前の右側へ展開。
- ただし、名前列の右端を超えてしまう名前や画面端では、既存の安全な範囲内に制限。画面端で左右反転するルールも維持。
- **探索起点は一切変更していない**：パンくず（論理パス）＋緑背景のListフォルダーだけが起点。メニュー表示位置の決定と独立。

### 4. 変更していないこと
- `/` トグル、Right/Left、Enter着地、カスケード、スクロール、キーボード操作
- 第1階層の名前列との幅同期、最大高さ＝List欄の高さ、タスクバーを避ける配置
- Expルート登録、Files List現在地、第3列アプリ状態
- ダークのFiles List背景色
