# FRB Launch / ナビ：長いフォルダーの固定枠スクロール・全件表示

- 基準: `launch_app_20261118_141431.zip`（2026-11-18）
- 変更対象: `src/slash_exp_navigation.py`
- 影響範囲: `/` ナビの項目数が多い列。既存Files Exp / Files Listのデータ構造・実行処理には変更なし。

## 原因と対応

1. 長いディレクトリを通常のQMenuに並べると、Qtが**ウィンドウ全体をスクロール**する。前版の位置復元処理がQtの移動と競合すると、選択行だけ進む・ちらつく・画面外へ消えるなどの不整合が起きる。
2. 表示行数が多い列は、検索欄＋QTreeWidgetの**固定されたスクロール領域**に切り替える。選択行は `scrollToItem(..., EnsureVisible)` で表示領域に追従。`QMenu` に毎回 `setActiveAction` を再実行しない。
3. 検索時は元のQActionではなく、**実際に表示されているQTreeWidgetItem** の表示状態を正にする。検索結果の再表示を先に行い、それから選択行を再決定する。ゼロ件→検索解除でも全件復帰する。
4. メニュー高さの上限（Launch高さ約70%）とファイル読み込み件数を分離。物理フォルダーのファイルは全件読み込み、スクロール対象とする。表示高さで一覧を途中打ち切らない。
5. ファイルのEnter実行は、従来Files Listで使う `preview_bookmark_from_list()` を優先し、その結果に従う。.md・Studio JSONが実際に第3列に表示されるか、外部エディターで開くかは**現行Files Listの設定・対象判定に準拠**。URLも既存判定を再利用する。

## 操作確認ポイント（Windows）

1. `/` → ダウンロード → `→`。大量ファイル・フォルダーが途中で省略されていないか。
2. `↓` を連打。枠は固定されたままリストだけがスクロールし、青い選択行が画面から消えないか。
3. 長い一覧を検索→検索解除。元の全件数に戻るか。
4. `.md`・Studio管理JSON・URLをEnter。Files Listで同じ項目をダブルクリックしたときと同じ結果になるか。
