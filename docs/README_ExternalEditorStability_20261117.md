# FRB Launch 第3列・外部エディター安定化試作（2026-11-17）

## ベース

`launch_app_20261117_135958.zip`（ユーザー提供の最新版）。本ZIPは差分のみ。

## 主な変更

1. **サクラエディタの2件目以降のファイル切替を安全化**
   - 以前は `txt/ini` のファイルを切り替えるごとに、今収容しているウィンドウを先にデスクトップへ退避・非表示にしていた。
   - サクラエディタはタブモードで同じウィンドウを再利用する場合がある。そこで、新しいファイルを開く要求は、**元のサクラエディタを表示したまま**発行する。
   - 既存HWNDのウィンドウタイトルが新しいファイルに変わった場合は、そのまま再利用。
   - 新しいHWNDが確実に見つかった場合のみ、古いHWNDを退避して新しい方を収容。
   - 検出不能やエラーの場合は、既存ウィンドウを優先して保護する。別ウィンドウができた場合はそちらで開いていることがある。
   - Obsidian等からサクラエディタへ戻る際は、Launch自身が退避したサクラエディタのウィンドウだけを再利用する。
2. **ObsidianのVault not foundを予防**
   - フォルダーに `.obsidian` があるだけでは、Obsidian URIで開けるVaultとは限らない。
   - `%APPDATA%\\obsidian\\obsidian.json` に登録されたVaultの配下にある `.md` だけをObsidianへ送る。
   - 登録されていない `.md` は従来のMarkdown Studioへフォールバックする。
3. **Obsidian埋め込み中のLaunchの不意な非アクティブ化を抑制**
   - QtがElectronの子ウィンドウにフォーカスを奪われて非アクティブと誤認する経路を抑制。
   - Obsidianの第3列「×」では、一度埋め込みを解除して非表示で保管。
   - 従来のStudioおよびBrowser Previewの動作は維持。

## 動作確認の順序（重要）

**作業中の未保存ファイルがない状態で**、事前にLaunchをバックアップして差分を上書き後、再起動。

- サクラエディタ: テスト用の `1.txt` → `2.txt` → `3.txt` → `1.txt` を順にダブルクリックして第3列の表示を確認。必ず各ファイルを編集→Ctrl+S→外で再読み込みして保存確認。
- サクラエディタ: 既存のサクラエディタをデスクトップに開いた状態でも、Launchがその無関係なウィンドウを勝手に収容しないか確認。
- Obsidian: Obsidian自身が管理しているVault内の `.md` をダブルクリック。第3列で編集・保存を確認。
- Obsidian: Vaultに登録していない `.md` が従来のMarkdown Studioで開くか確認（`Vault not found`ダイアログが出ないこと）。
- 両方: 第3列の「×」→再表示、別エディターへの切替、Launch終了時に編集済みファイルの内容が保持されるか確認。
