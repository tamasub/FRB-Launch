## 今回の再現条件

```
001.txt → 002.txt → 003.txt → 001.txt → 002.txt
   OK         OK         OK         OK         NG
```

最終操作で第3列に「サクラエディタの切替を確認できませんでした。現在の編集画面は保持しています。」と出る。

## 変更のねらい

前版は新規作成されたサクラのウィンドウと、現在取り込み中の同一 HWND のタイトル変化だけを主に確認していた。しかしサクラのタブグループでは、いったん開いた文書に戻ると、**新規 HWND が発生しない**ことがある。

今回、既にLaunchが収容・退避した **検証済み HWND** をファイルキーで引き当てて復帰させる経路を加えた。

- `src/studio_preview_panel.py`
  - `_restore_known_sakura_guest()` を追加。**同じLaunchで以前開いたファイルのウィンドウ**だけを復帰させる。
  - 以前のウィンドウが有効で、タイトルが指定ファイルを示す場合のみ採用。未確認のデスクトップウィンドウは取り込まない。
  - 復帰時は古い収容状態を保持・退避し、新しい収容先へ表示を移す。**閉じる／強制終了／ファイル保存はしない**。
  - 復帰が成立しなければ、既存の `sakura.exe` 呼び出しと新規ウィンドウ検出に戻る。
  - 現在の収容が無い状態から戻す際も、ファイルキー一致を優先。
- `tests/test_sakura_guest_revisit_20261119.py`
  - 再選択を含む連続切替、未確認・別ファイル HWND の拒否を自動テスト。

## 適用

1. 未保存データを安全に保存または別途保護して、Launch と試験用サクラのウィンドウを終了する。
2. **前回の WhitePaneFix が適用された状態**の FRB Launch ルートへ、差分ZIPのフォルダー構造を保ったまま上書きする。
3. `_run_windows_Try_Sakura_Overlay.bat` で起動する。
4. `001.txt → 002.txt → 003.txt → 001.txt → 002.txt` を実行し、毎回 **第3列のタイトル／サクラのネイティブタイトル／本文** が一致するか確認する。
5. `003 → 002 → 001 → 003`、必要なら別の `.txt` でも再選択を確認する。

## 注意

Windows実機でのサクラエディタの HWND / タブの構成は未確認。今回の修正は**検証済みの退避ウィンドウを直接復帰**させるもので、サクラ側が同一 HWND で全タブを管理し、かつ `sakura.exe` 再呼び出しでもアクティブタブが変わらないケースまでは保証しない。その場合は次にネイティブのタブ切替コマンドを検討する。

`state.ini`、ビルドBAT、Obsidian・VS Codeコード、Studio NativeShell は今回変更しない。
