# FRB Commander 左右キーによる項目・ボタン移動（2026-11-25）

## 目的・判断
候補ウィンドウが閉じている状態で、選択項目からコマンドコピー・実行へマウスなしで移動する。既存の選択項目間の左右移動を拡張し、ViewDef・PS1・コマンド生成・共通確認応答の仕様は変更しない。

## 操作契約
- 左右キーの移動順は表示中の選択項目（左から右）→コマンドコピー→実行。左キーは逆順。端で停止し、循環しない。
- コピー／実行ボタンが無効なときは移動対象に含めない。候補表示中、Keyboard Exのファイル選択中、確認応答中はこの移動を行わない。
- ボタンに実際のキーボードフォーカスを与え、青枠で現在位置を示す。ボタンにフォーカスがあるときは選択項目の青枠を消す。候補表示のアンカー用の選択項目インデックスは保持する。
- 選択項目上のEnter・下キーなどは従来どおり候補を表示。ボタン上のEnterはそのボタンを実行（コピーのみ、または確認応答）。Ctrl+Enterは従来どおり実行確認。コピー後もコピー位置を維持する。確認応答のNo後は従来どおり選択項目へ戻る。
- 候補ウィンドウでの右・左・Enter・上下・IME入力は既存の経路を維持。候補ポップアップおよびKeyboard Exの実装は変更しない。
- Tabでも選択項目のフレーム→コピー→実行の順を設定（項目内移動は左右キー）。

## 検証
- 変更前 Commander関連: 24 PASS / 3 SKIP。
- 変更後 Commander関連: 27 PASS / 4 SKIP。追加の非Qtテスト3件はPASS、追加Qtテスト1件はSKIP。
- 共通ダイアログ契約・共通コンテキストメニュー契約: PASS。
- Linux検証環境にはPySide6がないため、実際のフォーカス・青枠・Windowsキー入力は未検証。

## Windows受入
1. 選択未完了のまま右キーを押しても無効なボタンに移動しない。
2. 選択完了後、最終項目から右キーでコピー→実行、左キーで逆順に戻れる。青枠が二重表示されない。
3. コピー上でEnterを押しても実行確認は出ず、クリップボードにコマンドが入る。右キー1回で実行へ進む。
4. 実行上でEnterを押すと確認応答が出る。Noでスクリプトは実行されない。Ctrl+Enterでも従来どおり確認応答が出る。
5. 候補表示中に左右・上下・Enter・IMEを使い、既存動作を確認する。ファイル選択中はKeyboard Exの操作を優先する。
