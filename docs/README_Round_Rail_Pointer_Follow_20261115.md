# FRB Launch — ぐりぐりレール：描画復旧＋自動移動ルール修正（2026-11-15）

## 起点

ユーザー提供の `launch_app_20261115_220520.zip` を正本とした**差分ZIP**。`src/` を含む相対パスを保持しています。起動中のLaunchを終了し、同じソースフォルダーへ上書き展開してください。

## 修正点

1. **空の丸ボタン／大量の描画例外を修正**
   - `src/launch_remote.py`: `QPointF` のimportを追加（ユーザー添付版には未反映でした）。
   - 円の外枠・縦点線・「ぐりぐり」「Exp」「List」を描画する `paintEvent` を `try/finally` で保護。描画時例外でも `QPainter.end()` を実行。
   - 画像中の `QBackingStore::endPaint()` は、今回の `NameError` による後続エラーと推測されます。SQLite/WebEngineのログは今回の直接的な丸ボタン描画エラーとは区別しています。
2. **丸ボタンの Exp 左半分ダブルクリック**
   - マウス自動移動 **ON**：従来のExp→List確定が成功したとき、**2回目のマウスリリース後**に丸ボタン**右半分**へポインターを移動。
   - マウス自動移動 **OFF**：Exp半円のダブルクリックを無効化。ダブルクリックの初回CLICKで予約されたExpシングルクリックタイマーも停止。
   - 2回目のリリース時に左側の操作対象へ戻してしまうイベントも抑制します。通常のリモコンWindowの長押し・ダブルクリックや、List右半分の動作は変更しません。
3. **コンテキストメニュー「Exp列へ戻る」「List列へ進む」**
   - 既存の共通ディスパッチ処理で、まず操作対象だけ切り替えます（これまでどおりフォルダーを勝手に遷移させません）。
   - **ON**：メニューを閉じた後、移動先列の**既存カレント行**へポインターを移動します。フォルダーExpでは現時点のQTreeView currentIndex、Files ListではQTreeWidget currentItemを使用します。
   - **OFF**：操作対象の切り替えのみ。ポインターを移動しません。
   - ONでも、メニュー選択後にユーザーが自分でポインターを動かした場合、マウスボタンが押されている場合、カレント行がない場合、描画領域外では移動しません。

## 確認手順（Windows）

1. アプリ終了後、ZIPをソースルートに上書き展開して `_run_windows.bat` で起動。
2. 設定「リモコン表示 → ぐりぐりボタンのみ」。丸いボタンの内部に「ぐりぐり」「Exp | List」と縦点線が見え、コンソールの `QPointF` NameError が消えること。
3. 「マウスポインター自動移動」ON：Exp半円でぐりぐり後にダブルクリック。成功したらListへ切り替わり、ポインターは**円内右半分**へ移動すること。
4. 同設定OFF：Exp半円でダブルクリックしても遷移せず、ポインターも動かないこと。シングルクリックは従来どおり。
5. Exp/List各々の右クリックメニューから「List列へ進む」「Exp列へ戻る」。ONなら**相手列のカレント行**に移り、OFFなら移動しないこと。
6. Exp列の幅を広げて、丸ボタンが列境界に追従する従来仕様が維持されていること。
