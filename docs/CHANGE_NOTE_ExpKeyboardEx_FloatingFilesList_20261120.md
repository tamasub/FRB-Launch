# FRB Launch — Exp Keyboard Ex「浮遊する Files List」改修

基準フルZIP：`launch_app_20261120_174511.zip`（ユーザー提供の最新ZIP）  
適用方式：ZIP内の同名ファイルをFRB Launchルートへ上書き。**過去差分への再適用は不要**。

## 今回の差分

### 1. Files Listと同じ家の外観
- Slash専用メニューのみ、`theme_palette()` の `panel / panel_border / text / selection / hover / search_*` を使って色を統一。ライト／ダーク両対応。
- QMenu外枠を10px角丸。Windows透過Popup＋実ウィンドウの角丸マスクを併用（CSSの内側だけ角丸問題を回避）。
- メニュー検索欄／スクロール型一覧の色も統一。別の通常コンテキストメニューは変更しない。
- Windowsによるネイティブの影はOS依存。独自の影効果はフォーカス・描画回帰を避けるため付加していない。

### 2. 「親フォルダーの右側に生える」表示位置
- **Files Listで緑背景のフォルダーが起点**：その選択行の上端＋名前列の右端から第1メニューを展開。
- **Files Expで現在フォルダーが見えていてフォーカスがある**：その行の上端＋Exp列の右端から展開。
- **該当のフォルダー行が見えない／ファイル選択／緑枠のみ**：従来どおり Files List「名前」ヘッダーを起点にする。
- 水平は右優先。画面右端に収まらなければ親の左へ反転し、作業領域内にクランプ。
- **表示位置は表示だけの責務**。`/` の探索起点（パンくず論理パス＋緑背景フォルダー）は変更しない。

### 3. 高さ
- 第1階層と子階層のメニュー最大高さは **Files Listの内容表示領域の高さを超えない**。
- Launchのウィンドウからはみ出してOK。現在のモニターの **availableGeometry** （タスクバー除外）に上下10pxの安全余白を置く。
- 親行の上端から通常のカスケード方式で開く。下端の余裕がなければポップアップ全体を上へずらす。
- 高さが足りない場合は既存QTreeWidgetスクロールで項目を閲覧。`/`、↑↓、→、Enter、←の操作は変更しない。

## Windows実機での確認ポイント
1. Light/Darkで `/` のメニューとListの背景・選択色が同系色になり、外側四隅が本当に丸い。
2. Listの緑背景フォルダーから `/` → その行の右側に子内容が表示される。
3. Exp欄でフォルダーがフォーカス中に `/` → そのExp行の右側へ表示される。
4. Listでファイル選択／緑枠のみ → パンくずを起点に名前列ヘッダー位置へ表示される。
5. ウィンドウを画面下へ移動した状態で `/` → タスクバーの少し上で止まり、長い一覧は内部スクロール。
6. 幅を変えた名前列・Rightによる子メニュー・Enterでの着地・`/` で閉じる挙動にデグレがない。

既存の検索・パンくず・Expルート登録・第3列アプリ操作には変更を入れていない。
