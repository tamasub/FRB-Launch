# FRB Launch — `/` Exp矢印ナビ 第2回修正（2026-11-18）

## 承認済みキー契約

- `/`: Exp/Listから新しい矢印ナビを開く
- `↑ ↓`: **選択のみ**。下位メニューを勝手に展開しない
- `→`: **下位階層へ進む**。現在の項目が末端なら、その項目の**既存コンテキストメニュー**を表示する
- `←`: **一段戻る**
- `Enter`: **途中では無効**。末端ではその項目を**直接実行**する
- 末端の `→` でコンテキストメニューを開いたら、コンテキスト内の操作項目が新たな末端となる。操作項目のサブメニューも `→` で進み、選んだ最終コマンドを `Enter` で実行する
- `Esc`: メニューを閉じる

## 修正

1. QMenu.addMenu() は ↑↓やポインターのハイライトだけで子メニューを自動表示する場合があるため、はじめは普通のQActionとして登録。`→` でのみ QAction.setMenu() を接続して展開する。`←` で解除。表示ヒントの矢印は文字として保持。
2. Files Exp はフォルダーしか格納しない。従来は `My Work → ZIP` など、子に実行コマンドしか存在しないカテゴリが「項目なし」になった。`/` ナビだけは元の Launch JSON 子ノード全体を読み、実行アイテムも表示する。物理フォルダー配下の実ファイルも対象。
3. 仮想実行項目の `Enter` は既存 `activate_virtual_launch_item()` を呼び、データを権威ある現在のLaunch JSONで再照合。実ファイルは `run_file_path()`、フォルダーは既存のFiles内部ナビに委譲する。
4. 末端の `→` は仮想項目＝既存の Launch JSON コンテキスト、物理フォルダー＝既存の Exp コンテキスト、ファイル＝既存の Files List コンテキストを呼ぶ。ここで別の実装を作らない。
5. 前回のキーボード初期フォーカス問題は、復元時に非表示の旧第一列 (`view.left`) にフォーカスしていたことが原因の一部。実際に表示される `embedded_files_exp`（またはFiles List）へフォーカス。保存エリア `files_exp` も `files` として互換化する。

## 影響範囲

`src/slash_exp_navigation.py`, `src/app.py`, `src/focus_session.py`, `tests/test_slash_exp_navigation_20261118.py`, `tests/test_last_current_restore_20261024.py`。
既存Exp/Listの標準キー処理には変更なし。表示中の `/` ナビだけ専用制約を適用する。

## 検証範囲

Qtを使わないテストダブルによる操作契約検証、Python構文検査、焦点復元/既存コンテキストの関連テスト **71件PASS（サブテスト11件もPASS）**。広めのテストで失敗した旧プレビュー検証4件は、添付元ZIPでも同じ失敗を確認したため今回の変更由来ではない。**Windows 11 実画面でのフォーカス移譲とQtサブメニュー表示は未検証**。GUIはユーザー環境で最終確認が必要。
