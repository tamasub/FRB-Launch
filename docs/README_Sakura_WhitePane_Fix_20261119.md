# FRB Launch / サクラエディタ第3列「白い本文」修正試験

対象元データ: `launch_app_20261119_180224.zip`

## 現象

1. `001666.txt` を開くと、サクラエディタのWindows標準タイトルバーが表示される。
2. 続けて `002.txt` / `004.txt` を開くと、既存のサクラウィンドウ内にタブは増えるが、本文や下部の状態欄が白くなり表示が不完全。
3. 既存ファイルに内容があるため、表示・再描画の問題を優先して検証する。原因確定はWindows実機検証後。

## 変更点

- `src/guest_window_overlay.py`: サクラはWindows標準のスタイル/拡張スタイルをそのまま保持し、Win32子ウィンドウを再描画する `refresh_document()` を追加。
- `src/obsidian_ime_overlay.py`: 共通Overlayに「native styleを保存する」分岐を追加。従来のObsidian・VS Codeのデフォルト動作は変更しない。`SetParent` は使わない。
- `src/studio_preview_panel.py`: 最初のサクラ表示、同一HWNDでのタブ切替、新HWND切替の3経路で、切替確定後に200ms遅延再描画を1回要求。別タブの切替中や別ウィンドウに切り替わった場合は再描画を中止。
- テスト3ファイル（既存2更新、新規1）を同梱。

**変更していないもの:** `state.ini`、起動/コンパイルBAT、FRB Studio NativeShell、Obsidian/VS Code固有の表示ポリシー、実ファイルの読み書き処理。

## 適用・試験手順

1. 編集中ファイルを安全に保存し、Launchと試験用のサクラウィンドウを閉じる（必要なら外に出してから閉じる）。
2. ZIPをFRB Launchのプロジェクトルートへ **フォルダー構造のまま上書き展開**。
3. `_run_windows_Try_Sakura_Overlay.bat` で起動。
4. 第3列で `001666.txt` → `002.txt` → `004.txt` と開き、各ファイルの本文/背景/ツールバー/状態欄が更新されることを確認。
5. 第3列の「外に出す」ボタンでデスクトップへ戻し、本文や編集内容が正常に残ることを確認。
6. ObsidianのMarkdownとVS Codeの編集画面も、普段どおり表示されることを確認。

## 留意点

- この修正は **Windows実機未検証の試験版**。画像とソースから推定した2つの描画要因（Win32ウィンドウスタイルの変更とタブ切替後の子ウィンドウ再描画）を軽減する。
- 出来上がるEXEの仕様変更はまだ行わない。試験用BATの `FRB_SAKURA_GUEST_OVERLAY=1` を使う。
- `FRBStudio.NativeShell.exe` のWebView2 disposed例外は別問題として扱う。
- もし白いままなら、①外に出した直後の表示、②サクラ単独起動時の表示、③Launchのログ、が切り分け材料になる。

## テスト

- サクラ画面スタイルを無変更で保持すること、スタイルを変更する共通Overlayの旧動作が維持されること、タブ切替時の GDI 再描画要求と同一HWNDガードを自動テスト。
- 関連テスト：61 PASS / 1つ既存の未同梱BAT参照テストを除外。
- 広めの141テストでは11 FAIL（基準ZIPでも同じ11 FAIL）。現行方式に置き換え済みの旧サクラ実装に対するテストが主因。修正による新規失敗は確認されていない。
