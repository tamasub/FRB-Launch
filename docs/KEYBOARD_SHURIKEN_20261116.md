# FRB Launch — List キーボード手裏剣（2026-11-16）

## 適用

`launch_app_20261116_210423(1).zip` を基準にした差分。ZIP 内の `src/` と `tests/` をアプリの同じディレクトリへ上書き配置。

## 仕様

- **Files Listにフォーカスがあるときだけ**、`PageUp` / `PageDown` の同方向**4連打**で、既存手裏剣スクロールエンジンによる滑走を開始する。
- 1〜3回目は従来どおりのQtネイティブのページ移動。4回目は手裏剣起動に充てる。
- 判定窓は**最大1.35秒**かつキー間隔**最大0.48秒**。方向変更、別フォルダー、別キー、待ち時間経過で連打をリセット。キーを押し続けた自動リピートは連打に数えない。
- 滑走中、進行方向の `↑` / `↓` は**加速**（1打=ホイール1ノッチ相当、×1.45）、逆方向は**減速**（×0.75）。連打による累積調整、速度倍率は既存ホイールと同じ 0.01〜4.0。
- 滑走中の `PageUp` / `PageDown` は無効化し、誤って親フォルダーへ移動したり、Qtネイティブのページ送りが重ならないようにする。
- `Esc` はその場で着地（表示位置の行へ既存ロジックでカレント引継ぎ）。Listクリックも既存どおり着地。スクロール終端では自然着地。
- **既存のList先頭行での `PageUp` → 親フォルダー**は維持。List途中からPageUp連打を始めて途中で先頭へ着いた場合は、連打中の親移動を抑止。4回目で既に上端なら滑走せず、意図しない親移動も起こさない。その後の独立したPageUpでは従来どおり親へ移動する。
- `Ctrl+PageUp/Down` によるページ切替、Files Expやほかの列、ファイル操作、マウスの手裏剣は変更なし。

## 実装箇所

- `src/keyboard_shuriken_gate.py` — Qtなしで検証できる4打判定。
- `src/app.py` — Files Listキーボードイベントへ接続。初期化中・ファイル名編集中の処理とは切り分け。
- `src/remote_shuriken_scroll.py` — 既存の自動手裏剣ターゲットにkeyboard起動を追加。既存加速・減速・着地はそのまま再使用。
- `tests/test_keyboard_shuriken_20261116.py` — 連打ゲート、キー処理、速度調整、着地、PageUp親遷移の回帰。

## Windows受入確認の順序

1. Listで下へ余裕のあるフォルダーを開く。`PageDown` 3打では通常ページ移動、4打目で滑走開始。
2. 滑走中、`↓` 連打で加速し、`↑` 連打で減速、`Esc` で着地する。
3. 途中の位置から `PageUp` 4連打で上向きに滑走。`↑` が加速、`↓` が減速。
4. Listの先頭行で単独 `PageUp` すると従来どおり親フォルダーへ移動する。
5. 途中から `PageUp` を連打して先頭に届いても、連打中に意図しない親移動をしない。
6. `Ctrl+PageUp` などの既存ショートカットや、ホイール手裏剣・マウスクリックを確認する。
