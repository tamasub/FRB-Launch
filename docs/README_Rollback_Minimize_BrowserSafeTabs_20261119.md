# FRB Launch 差分 — 最小化統一の安全ロールバック + Browser非破壊タブ

基準ZIP: `launch_app_20261119_211653.zip`（2026-11-19 21:16頃）

## 目的

- 2026-11-19の「第3列から外部アプリを一律最小化して退避」実験を取り消し、直前に動作していたアプリ別処理へ戻す。
- VS Codeの固定プロファイル（ログイン・テーマ維持）、サクラの複数TXT切替・再収容など、それ以前の成功済み変更を残す。
- LaunchのFiles ListなどからURLを開く際、Browserの既存Webタブを勝手に上書きしない。

## 変更した操作

### 第3列の外部アプリ

- `studio_preview_panel.py` / `expanded_view.py`：最小化統一直前の実装へ戻す。
- 「×」と「外に出す」は別操作。アプリごとに以前の解除・閉じ方へ復帰する。
- 以前のサクラから他エディターへ切り替える際の確認や制限も戻る。今回はその改善には踏み込まない。
- `src/vscode_guest_bridge.py` は**変更なし**。Launch専用の固定プロファイル `profile-v1` は維持。
- `state.ini`、EXEビルドBATには変更なし。

### Browser

- Files Listから**異なるURL**を開く場合、既存のページを残したまま**新規タブ**を使う。
- **既に現在表示中のURLと一致するタブ**があれば、そのタブを選ぶだけ。再読み込みはしない（入力内容を保護）。
- 初回でタブが未作成、またはカレントが本当に空白なら、そのタブを利用できる。
- BrowserのUIから明示的に「カレントタブ」を選んだ場合だけ、従来どおりそのタブのページを切り替えることができる。
- Browserを第3列から隠しても、進行中の通信を `stop()` で停止させない。
- Browserを含む**Launchプロセス自体の終了**では、メモリ上の未保存Web入力を保存・復旧する保証はない（今回の対象外）。
- 開き直すタブの照合は**現在表示中のURL**で行う。ログイン等のリダイレクトでURLが変わっていれば、新規タブを作る安全側の動作になる。

## 適用方法

1. 現在のLaunchを通常の「終了」操作で終了する。黒いコンソールの×は終了経路が違うため使用しない。
2. `launch_app_20261119_211653.zip` 相当の作業フォルダーに、この差分ZIPの内容をルートから**上書き展開**する。
3. これまでの試験用 `_run_windows_Try_Overlay.bat` など、実際に使用していたBATで起動する。
4. 下の回帰試験を確認する。

なお、前回の試験差分で新設された `src/third_column_window_state.py` と `src/studio_release_lifecycle.py` は、新コードからは呼ばれない。すぐ削除する必要はない。完全なソース整理を希望する場合のみ、検証後にこの2ファイルを退避・削除できる。

## 実機チェック（Windows側でお願いしたい項目）

1. JSONをVS Codeで開く → 別プレビューに切り替える → 再選択。以前の方式で再収容できるか。
2. VS Codeを明示的に外に出す。ログイン状態・テーマが保持されるか。
3. TXTを 001→002→003→001→002 で切り替える。未保存内容が保護されるか。
4. Browserで URL-A→URL-B → URL-A。最初は2タブになり、最後は既存のAに戻るか。
5. BrowserのAでフォームを入力途中にして、Files ListからBへ移動する。Aの入力が残るか。
6. Browserを隠して再表示する。既存タブが維持されているか。
7. 「外に出す」と「×」の操作が同じになっていないことを確認。
