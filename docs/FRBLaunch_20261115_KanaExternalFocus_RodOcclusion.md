# FRB Launch 差分：かなフリックの外部入力先追従＋ワープ差し棒の重なり保護

適用元：`launch_app_20261115_151842.zip`（2026-11-15）

## ① かなフリック：起動後でも外部アプリの入力先を選び直せる

- かなフリック起動中、Windows の外部ウィンドウがアクティブな間、入力フォーカスを約65ms周期で観測します。**Windowsのフォーカスを勝手に変更しません**。
- サクラエディタなど、別アプリの編集箇所をクリックすると、その時点のトップレベルHWNDとフォーカスHWNDを次の送信先として記憶します。
- かなフリック自身のIME入力欄は送信対象にしません。外部のフォーカスが見つからなければ以前の外部宛先を解除します。
- 従来のLaunch内部QLineEdit等を選択して送る機能、入力選択の置換、送信前のフォーカス一致検証は維持します。
- 送信ボタンを押した後の110ms待機中に送信先が変わったら送信を中止します。
- 「外側クリックで閉じる」がONでも、**かなフリックを開いている間は**外部アプリをクリックしてもRemote/かなフリックを閉じません。かなフリックを閉じると通常の外側クリック挙動に戻ります。
- 送信先名は「送信」ボタンのツールチップで確認できます。

### Windows動作確認

1. `_run_windows.bat` を起動。Remote → かなフリックを開き、未確定のIME変換を確定しておく。
2. サクラエディタの空文書とかなフリックが**両方見える位置**に配置。かなフリックに「こんにちは」と入力。
3. かなフリックを閉じずに、サクラエディタの本文をクリックして挿入カーソルを置く。
4. かなフリックの「送信」ボタンにマウスを乗せ、ツールチップの送信先がサクラになっていることを確認。
5. 「送信」をクリック → サクラの現在のカーソル位置に文字が入力されることを確認。
6. メモ帳など別アプリの入力欄へ切り替えて再度「送信」。最新の選択先にだけ送られることを確認。
7. かなフリックを閉じ、元の「外側クリックで閉じる」設定の挙動に戻ることを確認。

**注意**：サクラエディタのカスタム入力領域で Win32 の `GetGUIThreadInfo` がフォーカス HWND を返さない場合は、送信先を取得できません。実機のサクラエディタで要確認です。また、別アプリがかなフリックを覆ってしまう場合は、画面を左右に並べて検証してください。

## ② ワープ差し棒：青い操作エリアの上に別ウィンドウがあると停止

- Win32 のトップレベルウィンドウのZ順を確認。青いエリアの矩形と、Remoteより前にあるウィンドウの**可視矩形**が少しでも重なれば操作を拒否します。マウスのある1点だけの判定ではありません。
- ホバー表示、ホイール、通常の行操作、Windowsマウス方式のクリック／ダブルクリック、SMART方式のカーソル移動を停止します。
- ブロック時にはガイド表示と予約クリックを解除します。重なりが解消すれば通常動作に戻ります。
- 非表示・最小化・DWMクローク・入力透過のウィンドウを除外。自分自身の描画用透明オーバーレイも除外します。
- Qtの論理座標をWin32ネイティブクライアント領域で補正して重なりを比較します。
- 判定が取得できなければ安全側で停止します。Windows以外の環境では従来のQtフォーカス判定を利用します。

### Windows動作確認

1. ワープ差し棒をONにし、青い操作エリアが正常に動くことを確認。
2. サクラエディタ等を**青いエリアの端だけに重ねる**。マウスは重なっていない青い部分に置く。
3. ホイール・クリック・ガイド表示・（該当モードなら）マウスワープが動かないことを確認。
4. 重ねたウィンドウを横へ移動し、再び動作することを確認。
5. 「ぐりぐり」中央ボタンと、重なりがない状態の従来操作が維持されることを確認。

## 適用

差分ZIPを `F:\FRB_Apps\FRB_Launch` に上書き展開し、開発版なら `_run_windows.bat` で確認できます。GitHubへ配布するときに限り `_build_windows.bat` で再ビルドしてください。

`UserConfig`、定義JSON、更新Feed、Updater、Release Managerは変更しません。
