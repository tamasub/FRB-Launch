# FRB Launch: サクラエディタ第3列・フォーカス共通化／非表示残留対策（試作）

## 適用ベース
- `launch_app_20261117_162843.zip`
- その後の `FRBLaunch_Obsidian_NativeKeyboardFocus_20261117_diff.zip` が適用済みの状態

## 対応
1. Obsidianで実績のある「第3列内の実クリック後にWin32入力フォーカスを渡す」処理をサクラエディタにも適用。
   - 既存のマウスフックと `focus_embedded_editor_from_click` を共用。
   - Files List、外部アプリ、非表示の編集画面にフォーカスを奪いにいかない。
   - 日本語IMEや Ctrl+S はサクラエディタが処理する。キーボード入力の擬似送信はしない。
2. 3つ目以降のファイル切替で使う `external_win32_host.editor_window_title()` の実装漏れを補完。
   - ウィンドウ収容後は子ウィンドウになるため、トップレベル列挙ではなく直接HWNDのタイトルを取得。
3. 別アプリ／別ウィンドウへの切替時、サクラエディタを不可視の状態で退避しない。
   - 通常ウィンドウに戻し、WM_CLOSE で通常終了を要求。
   - 未保存データがある場合、アプリ自身の保存確認に委ねる。
   - キャンセルされた場合は通常のデスクトップウィンドウで残り、強制終了しない。
   - ObsidianとStudioの保持方式は変更しない。

## 注意
- Windows上での実画面操作、IME、保存、複数タブ、サクラエディタ単独再起動は未検証。
- サクラエディタはコントロールプロセスと編集ウィンドウが分かれる構造。WM_CLOSEはウィンドウへ送る通常終了要求であり、プロセス一覧が必ず0になる保証ではない。
- 現在、サクラエディタの外部ウィンドウ収容は実験機能。埋め込みをオフにして通常起動することも可能。

## 確認の順番
1. テスト用 1.txt を第3列で開き、本文をクリック→文字入力（日本語IME含む）→Ctrl+S。
2. 2.txt→3.ini と切替後、文字入力と保存が維持されるか。
3. 第3列の×で閉じる→サクラエディタを単独起動できるか。
4. 未保存のテストファイルを使い、×→保存確認表示→キャンセル時に内容が保持されるか。
5. ObsidianとStudio、第3列Browser Previewに回帰がないか。
