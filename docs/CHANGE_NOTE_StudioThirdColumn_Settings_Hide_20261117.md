# FRB Launch 改修：Studio第3列「×で非表示」／メニュー設定／オプション設定

対象ベース: `launch_app_20261117_131841.zip`

## 仕様

1. Files List から `.md` および Studio管理下の `.json` をダブルクリックしたとき、従来どおり既存C# NativeShellを第3列で表示する（Studio本体の保存機能を使用）。
2. **Studio第3列の「×」は表示欄を隠すだけ**。C# NativeShellは終了も独立ウィンドウへの復帰もさせない。同じファイルをもう一度ダブルクリックすると編集中の画面へ戻る。
3. 別のStudio対象へ切り替えた場合は、以前のNativeShell HWNDを隠して保持する（編集内容を勝手に破棄しない）。そのファイルを再選択すると復帰する。
4. メニューの「メニュー設定 (FRB Studio)」、各Page/ItemのStudio編集操作は、Files画面表示中は同じ第3列へ表示する。`--launch-home`、`--launch-view-def`、`--launch-page-id`、`--launch-item-id` など既存の起動引数はそのまま渡す。
5. メニューの「オプション設定...」は、Files画面表示中、第3列へ表示する。既存 `OptionSettingsWindow` のWebEngine画面とNodeサーバー保存処理をQt子ウィジェットとして利用する。
6. Compact表示など第3列のない場合、従来どおり別ウィンドウで起動する。
7. Browser Previewの動作は維持。Browser→Studio、Studio→Browserのどちらの順序でも、プレビュー表示先は右端の第3列となる。

## 保存・終了時の安全性

- 「×」では**Studioのプロセスを終了しない**。未保存の編集は画面内に保持される。
- **Launch本体を終了するとき**は、保持中のC# Studioをデスクトップの通常ウィンドウに戻す（未保存の編集を失わないため）。これは「×」とは別の動作。
- 異なるStudioファイルを多数開くと、それぞれのStudioプロセスが保持されメモリを使用する。長時間連続で多数のファイルを開く場合は注意。
- オプション設定は既存のNodeサーバーで保存。第3列の「×」で隠した場合は画面とサーバーを保持し、Launch終了時に停止する。
- Studio NativeShellのコードは変更していない。C#→Python移植なし。

## Windowsでの動作確認手順

1. Launchを再起動し、編集用のコピーを使ってStudio管理下のJSONをFiles Listからダブルクリック。第3列にStudioを表示。
2. Studioのグリッドを編集し、**あえて保存せず**第3列の×を押す。Studioの独立ウィンドウが現れないことを確認。
3. 同じJSONをもう一度ダブルクリック。編集中の内容が残っていることを確認。
4. Studioで保存し、再読込後も変更が残ることを確認（書き込み確認）。
5. 別のJSONやMarkdownを開き、元のJSONを再度選択して同じ画面に戻れることを確認。
6. Launchの設定メニュー→「メニュー設定 (FRB Studio)」を選択。第3列でメニュー編集画面が表示され、編集対象のPage/Item指定が効くことを確認。保存後の反映は従来の仕様に従う。
7. Launchの設定メニュー→「オプション設定...」を選択。第3列でオプション画面が表示されること、保存できることを確認。反映に再起動が必要な項目は従来どおり。
8. Browserブックマークのプレビューへ切り替え、第3列表示に問題がないことを確認。
9. 未保存のStudioを保持した状態でLaunch本体を終了し、独立Studioウィンドウとして復帰することを確認。未保存の状態はStudioで保存／破棄を判断。
